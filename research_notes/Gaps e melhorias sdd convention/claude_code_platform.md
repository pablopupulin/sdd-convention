# Claude Code plugin / skills / hooks platform and cross-agent standards (state as of 2026-11-12)

All "Cited Findings" were read from the linked page on 2026-11-12 unless another date is given. Version numbers ("requires v2.1.x") are quoted from the official docs. Pages are long; where only part of a page was read this is listed under Gaps.

## 1. Claude Code plugins: plugin.json / marketplace.json schema, components, distribution

### Takeaway
The plugin surface is far larger than skills + commands + one hook: `userConfig` (typed, prompted options), `dependencies`, `bin/` executables, `${CLAUDE_PLUGIN_DATA}`, plugin agents, MCP/LSP servers, output styles, workflows, experimental monitors/themes/evals, and a first-party `claude plugin validate --strict` / `claude plugin eval` / `claude plugin tag` toolchain. Distribution now has three routes (no marketplace, own marketplace, Anthropic's directory via a developer portal); `claude-plugins-official` does not take open submissions.

### Cited Findings

**Manifest**
- The manifest is optional; `name` is the only required key. Top-level fields: `$schema`, `name`, `displayName`, `version`, `description`, `author`, `homepage`, `repository`, `license`, `keywords`, `metadata`, `icon`, `documentationUrl`, `supportUrl`, `privacyPolicyUrl`, `termsOfServiceUrl`, `defaultEnabled`, `dependencies`, `settings`, `userConfig`, `types`, `channels`, `skills`, `commands`, `agents`, `hooks`, `mcpServers`, `lspServers`, `outputStyles`, `workflows`, `experimental` (`themes`, `monitors`, `evals`). — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Unknown top-level keys are stripped with a validate warning; unknown keys inside `userConfig` options, `channels`, `lspServers`, `monitors` entries are errors and the plugin does not load. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Plugin `name` must be kebab-case; names starting with `claude-`, `anthropic-`, `cc-plugin-` etc. are reserved (error). — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Component paths must start with `./`, resolve inside the plugin root and exist. `commands`, `agents`, `outputStyles`, `workflows`, `experimental.themes`, `experimental.monitors` REPLACE the default folder; `skills` ADDS to `skills/`; `hooks`, `mcpServers`, `lspServers` MERGE with the default file. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Standard layout: `skills/`, `commands/` ("Prefer `skills/` for new plugins"), `agents/`, `hooks/hooks.json`, `.mcp.json`, `.lsp.json`, `output-styles/`, `workflows/`, `themes/`, `monitors/monitors.json`, `bin/`, `settings.json`. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- `bin/`: files are on the Bash tool's `PATH` while the plugin is enabled, so Claude runs them as bare commands. Caveat: claude.ai and Cowork do not install a plugin that has a top-level `bin/` directory. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- `settings` / root `settings.json`: only `agent` and `subagentStatusLine` take effect; other keys are dropped. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- "A `CLAUDE.md` at the plugin root isn't loaded as context, and `claude plugin validate` warns when it finds one. To include instructions that load into Claude's context, put them in a skill." — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)

**userConfig**
- `userConfig` options: `type` (`string`, `number`, `boolean`, `directory`, `file`), `title`, `description` (all three required), `required`, `default`, `options` (fixed picker, requires v2.1.271; declaring it makes the plugin unloadable on older versions), `multiple`, `sensitive` (secure storage), `min`/`max`. Values are prompted at enable time and shown as rows in `/config` (v2.1.269+). — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Non-sensitive values are stored under `pluginConfigs` in the user's `settings.json`. They are referenced as `${user_config.KEY}` (MCP/LSP config, exec-form hook `args`, skill and agent content) or as env var `CLAUDE_PLUGIN_OPTION_<KEY>` in hook processes. Shell-form hook commands and monitor commands reject `${user_config.*}`. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)

**Path variables**
- `${CLAUDE_PLUGIN_ROOT}` = installed version directory (changes on every update, do not write state there). `${CLAUDE_PLUGIN_DATA}` = `~/.claude/plugins/data/<id>/`, kept across updates, deleted on uninstall unless `--keep-data`. `${CLAUDE_PROJECT_DIR}` = project root. All three resolve in hook `command`/`args`, MCP/LSP config and the Markdown body of skills, commands and agents; they are NOT in the environment of Bash-tool commands. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- On Windows, substituted paths use forward slashes except in exec-form hooks and PowerShell hooks, which keep backslashes; PowerShell is the default hook shell on Windows when Git Bash is not installed. `claude plugin validate` warns on an unquoted path variable in a shell-form hook. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)

**Monitors, dependencies, Node deps**
- `experimental.monitors` entries: `name`, `command`, `description`, `when` (`"always"` or `"on-skill-invoke:<skill>"`); a persistent background process; does not start with `-p`; does not load for repository (project-scope) plugins. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference); [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)
- `dependencies`: `"name"`, `"name@marketplace"` or `{name, marketplace, version}` with a semver range; installing the plugin installs and enables the dependency; version ranges resolve against git tags of the form `{name}--v{version}` created by `claude plugin tag [--push]`. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Node dependencies: if the plugin root has `package.json` plus `package-lock.json`/`npm-shrinkwrap.json`/`bun.lock`, Claude Code installs them into the cached copy with `--ignore-scripts`, registry packages only, 60-second timeout. Python dependencies are not auto-installed; the docs say to install them from a hook into `${CLAUDE_PLUGIN_DATA}`. — [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)

**Versioning and updates**
- Version resolution order: manifest `version`, then marketplace entry `version`, then the 12-char commit SHA for git sources. A pinned `version` that is not bumped means `claude plugin update` prints "already at the latest version" and users keep the old copy. Alternative: omit `version` so every commit is a new version. — [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md); [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Auto-update default: on for Anthropic's official marketplaces such as `claude-plugins-official`, off for every third-party marketplace (user toggles "Enable auto-update" under `/plugin` Marketplaces, or `autoUpdate` on an `extraKnownMarketplaces` entry). It runs up to ten minutes after the first message; the session keeps the loaded version until `/reload-plugins`. — [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)
- Previous version directories are removed 14 days after update. — [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)
- Never rename a published plugin; use `displayName` for the label, or the marketplace `renames` map if unavoidable. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)

**Marketplace**
- `marketplace.json` requires `name`, `owner`, `plugins[]`; each entry needs `name` and `source`. Source types: relative path, `github`, `git-subdir`, `url`, `archive`, `npm`, `command`. For a repo that is its own marketplace the documented form is one entry with `"source": "./"` and the same `name` as `plugin.json`. — [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces); [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Entry `strict` defaults to `true` (entry appends components to the manifest). Entry/manifest name mismatch causes "not found in marketplace" on install. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference); [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)
- One-command install: `/plugin install <name> --marketplace <owner/repo>` (v2.1.275+) and `claude plugin install <name> --marketplace <owner/repo>` (v2.1.292+). — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Project sharing: list the plugin under `enabledPlugins` in `.claude/settings.json` (with `extraKnownMarketplaces`), or place the plugin directory under `.claude/skills/` (loads as `<name>@skills-dir`). "Claude Code doesn't scan a project's `.claude/plugins/` directory." Cloud sessions do not add repo-declared `extraKnownMarketplaces`. — [Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)
- Without a marketplace: `claude --plugin-dir <dir or .zip>`, `--plugin-url <zip>`, or drop the plugin under `~/.claude/skills/`. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)

**Anthropic channels**
- Anthropic's directory (https://claude.ai/directory) is submitted through the developer portal at https://claude.ai/directory/manage; requires a paid claude.ai plan and a GitHub repository; one listing reaches claude.ai, Cowork and Claude Code (loads as `<name>@synced`, terminal sync requires v2.1.273+). Listing metadata comes from `icon`, `documentationUrl`, `supportUrl`, `privacyPolicyUrl`, `termsOfServiceUrl` in `plugin.json`. The portal applies checks beyond `claude plugin validate --strict`. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- "Anthropic's official marketplace, `claude-plugins-official`, doesn't take submissions through the directory portal. If you work with an Anthropic partner contact, ask them about an official-marketplace listing." — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Some components are Claude Code-only and do not load on claude.ai/Cowork; a component support table is at https://claude.com/docs/plugins/platform-support (not fetched). — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)

**Tooling**
- `claude plugin validate [--strict] <dir>` validates plugin and marketplace; `--strict` turns warnings (unknown field, missing `version`/`description`/`author`, non-kebab name) into exit code 1 for CI. Also `claude plugin init`, `claude plugin details`, `claude plugin list`, `claude plugin tag`, `claude plugin eval`. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference); [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)
- Pre-release checklist in the docs: permanent name, versioning decision, `validate --strict`, install from a local marketplace, fill `description`/`author`/`homepage`/`repository` + root `README.md`, run the eval suite. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)

### Inferences
- For sdd-convention, the unexploited manifest features with the clearest fit are: `userConfig` (e.g. docs root path, enforcement level "remind" vs "block", language) read via `CLAUDE_PLUGIN_OPTION_<KEY>` in the Python hook; `bin/` to expose the docs linter as a bare command (at the cost of claude.ai/Cowork installability); a plugin agent (e.g. a docs-auditor subagent); `experimental.evals`; directory-listing fields if submitting to Anthropic's directory.
- The repo-as-own-marketplace pattern is officially documented (`"source": "./"`); the plugin should check that entry name equals manifest name and decide explicitly between bumping `version` each release and omitting it.
- Because third-party marketplaces do not auto-update by default, the README should tell users to enable auto-update or run `claude plugin update`.
- Because Python dependencies are not auto-installed, the plugin's stdlib-only choice remains the right one.
- The two commands in `commands/` could be migrated to `skills/` (docs: "Prefer `skills/` for new plugins").

### Gaps
- The full marketplace reference (https://code.claude.com/docs/en/plugins/marketplace-reference.md: every entry field, `renames`, release channels, `strictKnownMarketplaces` details) was not fetched; "release channels" is unverified.
- The `anthropics/claude-plugins-official` repository and the claude.com submission/pre-submission checklist pages were not inspected; review criteria and timelines are unknown.
- No reliable source was collected on community directories (third-party plugin indexes); none are cited here.
- The plugin components page (https://code.claude.com/docs/en/plugins/components.md) with runtime details for agents/output styles/workflows was not fetched.

## 2. Hooks: events, handler types, decision control; best fit for "inject spec index" and "enforce doc updates"

### Takeaway
There are now 33 hook events and five handler types (`command`, `http`, `mcp_tool`, `prompt`, `agent`). A `SessionStart` hook returning `additionalContext` is the documented way to inject an index at start (and again on `compact`), while `Stop` now supports a non-error `additionalContext` nudge in addition to `decision: "block"`; `PostToolUse`, `FileChanged`, `TaskCompleted` and `InstructionsLoaded` are complementary options.

### Cited Findings
- Events: `SessionStart`, `Setup`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `MessageDisplay`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult`, `SessionEnd`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Can block (exit 2 / decision): `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PostToolBatch`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `TeammateIdle`, `ConfigChange`, `WorktreeCreate`, `PreCompact`, `PreModelSwitch`, `Elicitation`, `ElicitationResult`. Cannot block: `SessionStart`, `PostToolUse` (tool already ran), `InstructionsLoaded`, `FileChanged`, `SessionEnd`, `Notification`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Handler types: `command`, `http`, `mcp_tool`, `prompt` (single-turn model evaluation), `agent` (subagent with tools, experimental, up to 50 turns). Prompt/agent response schema: `{ "ok": true }` or `{ "ok": false, "reason": "..." }`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Common handler fields: `type`, `if` (permission-rule syntax such as `"Bash(git *)"`, one rule, only evaluated on `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`), `timeout` (defaults 600s command/http/mcp_tool, 30s prompt, 60s agent), `statusMessage`, `once` (skill frontmatter only). Command fields: `command`, `args` (exec form, no shell), `async`, `asyncRewake` (background; wakes Claude on exit 2), `shell` (`"bash"` or `"powershell"`), `onFailure` (`"continue"`/`"block"`, v2.1.295+). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Universal JSON output: `continue`, `stopReason`, `suppressOutput`, `systemMessage`, `terminalSequence`. `additionalContext` (inside `hookSpecificOutput`) is supported by `SessionStart`, `SubagentStart`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Stop`, `SubagentStop`, `PostModelSwitch`; each string is capped at 10,000 characters (longer output is saved to a file with a 2,000-character preview). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `SessionStart`: matcher on `source` = `startup`, `resume`, `clear`, `compact`, `fork`. Output: `additionalContext` (plain stdout also works), `initialUserMessage`, `sessionTitle`, `watchPaths` (absolute paths for `FileChanged`), `reloadSkills`. `CLAUDE_ENV_FILE` persists env vars. Claude's first response waits for the hook. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `Stop`: input includes `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`. Output: `decision: "block"` + `reason`, or `hookSpecificOutput.additionalContext`, described as "Non-error feedback for Claude ... shown in the transcript as hook feedback rather than a hook error"; the docs' own example is "run the test suite before finishing". An 8-consecutive-continuation cap applies (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`). Does not run on user interrupt. `/goal` is a built-in session-scoped prompt-based Stop hook. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `PostToolUse`: matcher on tool name; input `tool_input`, `tool_response` (for Bash, `tool_response.bashEditDiff` lists changed files, v2.1.269+); output `additionalContext`, `decision: "block"` with `reason` (adds the reason next to the result). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `PostToolBatch`: fires once after a parallel batch of tool calls, no matcher, `additionalContext` injected once. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `FileChanged`: filesystem watcher, fires regardless of what changed the file; `matcher` is a `|`-separated list of literal filenames in the working directory (not regex); dynamic paths via `watchPaths` from `SessionStart`/`CwdChanged`/`FileChanged`; no decision control and it is not in the `additionalContext` list (only `systemMessage` and `watchPaths` are read). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `InstructionsLoaded`: fires when a CLAUDE.md or `.claude/rules/*.md` loads; matcher on `load_reason` (`session_start`, `nested_traversal`, `path_glob_match`, `include`, `compact`); observability only, no decision control. Does not fire for an `AGENTS.md` read through the Project instructions setting. — [Hooks reference](https://code.claude.com/docs/en/hooks); [Memory](https://code.claude.com/docs/en/memory)
- `TaskCompleted` and `TaskCreated` are blockable events tied to the task list (`TaskCreate`). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `UserPromptSubmit`: `additionalContext`, `decision: "block"`; default timeout lowered to 30 seconds. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Plugin hooks: `hooks/hooks.json` wraps the event map in a top-level `"hooks"` key; inline manifest hooks are the bare event map. Hook processes receive `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PROJECT_DIR`, `CLAUDE_PLUGIN_OPTION_<KEY>`. The docs recommend exec form (`command` + `args`) "so each path is one argument with no quoting". — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)
- Skills can register hooks through the `hooks` frontmatter field: "Hooks registered when the skill is invoked and kept for the rest of the session." — [Skills](https://code.claude.com/docs/en/skills)
- Windows: `"shell": "powershell"` on a command hook runs it in PowerShell (auto-detects `pwsh.exe`, falls back to `powershell.exe`). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- The memory docs state that a `SessionStart` hook that prints `AGENTS.md` should be removed once Claude reads the file natively because "the hook adds a second copy to the context". — [Memory](https://code.claude.com/docs/en/memory)

### Inferences
- "Inject the index of active specs at session start": a `SessionStart` hook (matchers `startup|resume|clear|compact`) that parses frontmatter in `docs/specs/` and returns a compact list of `status: active` specs as `additionalContext` fits directly. Keep it well under the 10,000-character cap. This is the same mechanism superpowers uses for its bootstrap (see section 6). Avoid duplicating content that CLAUDE.md already loads.
- "Remind/enforce doc updates": the current single Stop hook can be refined rather than replaced. Options, from soft to hard: (a) Stop with `hookSpecificOutput.additionalContext` instead of `decision: "block"` for a reminder that is not rendered as a hook error; (b) Stop with `decision: "block"` only in an "enforce" mode selected through `userConfig`; (c) `PostToolUse` with matcher `Edit|Write` giving an immediate `additionalContext` nudge when source files change without a spec/ADR change, or validating frontmatter right after a spec file is written; (d) `TaskCompleted` to gate task completion on docs being updated when the task list is in use; (e) a `prompt` or `agent` Stop hook to judge semantically whether behavior changed (costs model calls; agent hooks are experimental).
- `FileChanged` is a poor fit for reminders to Claude because it cannot return `additionalContext`; it could at most show a `systemMessage` to the user.
- Exec-form hooks (`command` + `args`) and `shell: "powershell"` may reduce the need for the polyglot `run-hook.cmd` wrapper, but locating the Python interpreter (`python` vs `python3` vs `py`) on Windows is not solved by the platform, so the wrapper may still be needed. Unverified; needs testing.
- Always honoring `stop_hook_active` remains required to avoid loops; the 8-continuation cap is a backstop.

### Gaps
- The sections on async hook limitations, security settings (`disableAllHooks`, `allowManagedHooksOnly`), `SessionEnd` reasons, `PreCompact`/`PostCompact` details, and `TaskCompleted` input fields were located in the page but not read in detail.
- Which events support `prompt`/`agent` handlers (full list) was not extracted.
- The hooks guide page (https://code.claude.com/docs/en/hooks-guide) was not fetched.
- I found no official statement on the recommended way to launch a Python hook cross-platform.

## 3. Skills: frontmatter, commands merge, budgets, evaluation tooling

### Takeaway
Custom commands and skills are one mechanism now (commands keep working, skills are preferred), with roughly 20 Claude Code frontmatter fields, of which only six are portable under the open spec. Evaluation is first-class: `claude plugin eval` (with a no-plugin baseline and CI thresholds), `/skill-doctor`, `/doctor prompt-audit`, and the skill-creator plugin.

### Cited Findings
- Frontmatter fields accepted by Claude Code: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort` (`low`..`max`), `context` (`fork`), `agent`, `background`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`. Unrecognized fields are ignored. — [Skills](https://code.claude.com/docs/en/skills)
- Portability limit: outside Claude Code (claude.ai uploads, the Skills API, `package_skill.py`) only `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` are allowed; any other key is a hard error such as `Unexpected key(s) in SKILL.md frontmatter: argument-hint`. — [Skills](https://code.claude.com/docs/en/skills)
- Listing budget: combined `description` + `when_to_use` is truncated at 1,536 characters in the skill listing; put the key use case first. The open spec caps `description` at 1,024 characters. — [Skills](https://code.claude.com/docs/en/skills); [Agent Skills specification](https://agentskills.io/specification)
- "Keep `SKILL.md` under 500 lines"; supporting files load only when referenced; scripts are executed, not loaded. After compaction Claude Code re-attaches the first 5,000 tokens of each invoked skill within a 25,000-token combined budget. — [Skills](https://code.claude.com/docs/en/skills)
- Commands merge: `.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`; command files support the same frontmatter except `name` and `paths`; a skill beats a same-named command file; "Prefer skills for new work". — [Skills](https://code.claude.com/docs/en/skills)
- Invocation control: `disable-model-invocation: true` = user-only (also blocks preloading into subagents); `user-invocable: false` = model-only. — [Skills](https://code.claude.com/docs/en/skills)
- `paths`: glob patterns limiting automatic activation to work on matching files. — [Skills](https://code.claude.com/docs/en/skills)
- Substitutions: `$ARGUMENTS`, `$ARGUMENTS[N]`, `$N`, `$name`, `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`. `allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)` lets a bundled script run without a permission prompt. — [Skills](https://code.claude.com/docs/en/skills)
- Dynamic context injection: `` !`command` `` inline or a ```` ```! ```` fenced block runs before Claude sees the skill and its output replaces the placeholder; a non-zero exit aborts the invocation (append `|| true`); can be disabled with `disableSkillShellExecution`. — [Skills](https://code.claude.com/docs/en/skills)
- Plugin skills are namespaced `/plugin-name:skill-name`. — [Skills](https://code.claude.com/docs/en/skills)
- Open-spec constraints: `name` 1-64 chars, lowercase alphanumerics and hyphens, must match the parent directory name; optional dirs `scripts/`, `references/`, `assets/`; progressive disclosure tiers of about 100 tokens metadata, under 5,000 tokens instructions, resources on demand; keep file references one level deep; validate with `skills-ref validate ./my-skill`. — [Agent Skills specification](https://agentskills.io/specification)
- `claude plugin eval` (v2.1.269+): suite lives in `evals/` (override with `experimental.evals` or `--eval-dir`), one directory per case with `prompt.md` (frontmatter: `max_turns`, `timeout_seconds`, `model`, `tags`, `allowed_tools`) and `graders/*.md`. Six grader types: `regex`, `tool_used`, `tool_order`, `file_exists` (free) and `llm`, `baseline` (judge model calls); "There are no custom-code graders." Each case runs three times with the plugin and three times without; a case passes when its score meets `--threshold` (default `1.0`); other flags include `--case`, `--runs`, `--ablation none`, `--judge-model`, `--allow-tools`. `claude plugin eval init` interviews the author and writes cases; `init --bare <name>` writes a template. Every run is a real model call billed to the account. MCP tools can be mocked under `evals/mocks/<server>/<tool>.md`. — [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals.md)
- The docs' "most common first finding" is a `tool_used: Skill` grader failing, "which means Claude isn't choosing your skill on natural phrasing. Adjust the skill's `description`". — [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals.md)
- `/skill-doctor` (v2.1.252+) shows each skill's context cost and usage; `/doctor prompt-audit` (v2.1.283+) audits CLAUDE.md, AGENTS.md, rules, skills, commands, subagents and output styles for outdated or conflicting instructions. — [Skills](https://code.claude.com/docs/en/skills); [Memory](https://code.claude.com/docs/en/memory)
- skill-creator plugin: `/plugin install skill-creator@claude-plugins-official`; stores tests in `evals/evals.json`, a format not compatible with `claude plugin eval`. — [Skills](https://code.claude.com/docs/en/skills); [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals.md)

### Inferences
- If sdd-convention wants one skill set for several agents, frontmatter in the shipped SKILL.md files should stay within the six spec fields (or accept that Claude-only fields are ignored by some clients and rejected by claude.ai uploads), with `name` equal to the directory name and `description` at or below 1,024 characters.
- Skill candidates for unexploited fields: `paths` (e.g. activate the spec-editing skill only for `docs/specs/**`), `allowed-tools` pre-approving the bundled linter script, `` !`...` `` injection to embed the live list of active specs or linter output into a skill, `context: fork` for an audit skill, `disable-model-invocation: true` for the scaffold/init command, `argument-hint`.
- A small `evals/` suite (should-trigger and should-not-trigger prompts with `tool_used: Skill` graders plus a `regex`/`file_exists` grader on produced docs) would give measurable evidence on trigger descriptions; cost is roughly cases x 6 runs.

### Gaps
- The last ~19,000 characters of the skills page (skill-creator walkthrough, "Skill not triggering" and "Claude stops following a skill" troubleshooting) were not read; official trigger-description best practices beyond "put the key use case first" and "what it does and when to use it" are therefore not captured here.
- No per-session total skill-listing budget figure (beyond the 1,536-character per-skill cap) was found in the portion read.
- The `anthropics/skills` repository was not inspected.

## 4. Agent Skills open standard, AGENTS.md, and multi-agent distribution

### Takeaway
SKILL.md is a widely adopted open format (originated by Anthropic) and AGENTS.md is stewarded by the Agentic AI Foundation under the Linux Foundation; Claude Code reads AGENTS.md natively since v2.1.277, but only when no CLAUDE.md exists on the path (by default). Multi-agent shipping is done per harness: superpowers keeps one `skills/` tree and adds a thin manifest folder per agent.

### Cited Findings
- "The Agent Skills format was originally developed by Anthropic, released as an open standard, and has been adopted by a growing number of agent products"; discussion at github.com/agentskills/agentskills; a client showcase is at https://agentskills.io/clients. — [Agent Skills overview](https://agentskills.io/home)
- Codex: skills are directories with `SKILL.md` plus optional `scripts/`, `references/`, `assets/`, `agents/`; scanned from `.agents/skills` (cwd up to repo root), `$HOME/.agents/skills`, `/etc/codex/skills`; invoked explicitly with `$skill-name` or `/skills`, or implicitly by description; optional `agents/openai.yaml` (`interface`, `policy.allow_implicit_invocation`, `dependencies.tools`); the skill list defaults to 2% of the context window; plugins distribute skills and can bundle MCP servers. — [Codex: build skills](https://learn.chatgpt.com/docs/build-skills) (redirect target of developers.openai.com/codex/skills)
- Gemini CLI: skills discovered from extension skills, `~/.gemini/skills/` or `~/.agents/skills/`, `.gemini/skills/` or `.agents/skills/` (the `.agents/skills/` alias takes precedence within a tier); activation through the `activate_skill` tool with a user confirmation; `gemini skills install <git url> [--scope user|workspace] [--path]`. — [Gemini CLI skills](https://geminicli.com/docs/cli/skills/)
- The Gemini CLI docs page carries a banner stating Gemini CLI was replaced by Antigravity CLI on June 18, 2026. — [Gemini CLI skills](https://geminicli.com/docs/cli/skills/)
- AGENTS.md: "a README for agents", no required fields, maintained by the Agentic AI Foundation under the Linux Foundation, "over 60k open-source projects"; nearest file in the tree wins. Listed tools include Codex, Jules, Factory, Aider, goose, opencode, Zed, Warp, VS Code, Devin, Junie, Amp, Cursor, RooCode, Gemini CLI, Kilo Code, GitHub Copilot coding agent, Windsurf, Augment Code. Claude Code is not in the list shown on the page. — [agents.md](https://agents.md/)
- Claude Code and AGENTS.md: "Claude Code can read `AGENTS.md` as your project instructions ... without adding a `CLAUDE.md`, an import, or a setting." Requires v2.1.277+. Default mode `claude-md-or-agents-md`: AGENTS.md is read only when there is no `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` in the working directory or above; `claude-md-and-agents-md` loads both; other values `claude-md`, `managed-only`. Fallback that works everywhere: a `CLAUDE.md` containing `@AGENTS.md` (preferred over a symlink on Windows). — [Memory](https://code.claude.com/docs/en/memory); conflicts with the [agents.md](https://agents.md/) tool list (Claude Code absent) and with secondary blog claims that Claude Code has no native AGENTS.md loading, which appear to predate v2.1.277
- `/import` in Claude Code brings another coding agent's configuration in (appends instruction files such as AGENTS.md to CLAUDE.md and carries over MCP servers, commands, subagents, skills). — [Memory](https://code.claude.com/docs/en/memory)
- superpowers multi-agent packaging: one repo with shared `skills/`, `hooks/`, `scripts/` and per-harness folders/files `.claude-plugin`, `.codex-plugin`, `.cursor-plugin`, `.agents/plugins`, `.antigravity-plugin`, `.devin-plugin`, `.hermes-plugin`, `.kimi-plugin`, `.muse-plugin`, `.opencode`, `.pi/extensions`, plus `AGENTS.md`, `GEMINI.md`, `gemini-extension.json`, `package.json`, `.version-bump.json` with `scripts/bump-version.sh` for version sync. — [obra/superpowers](https://github.com/obra/superpowers)
- superpowers install commands per harness: Claude Code `/plugin install superpowers@claude-plugins-official`; Codex CLI `/plugins` search; Cursor `/add-plugin superpowers`; Gemini CLI `gemini extensions install https://github.com/obra/superpowers`; GitHub Copilot CLI `copilot plugin install superpowers@superpowers-marketplace`; OpenCode via `.opencode/INSTALL.md`; also Antigravity, Devin CLI, Factory Droid, Grok Build CLI, Kimi Code, Pi, Qwen Code, Hermes Agent, Muse. Users must install separately per harness. — [obra/superpowers](https://github.com/obra/superpowers)
- Secondary (unverified against primary sources): "Agent Plugins 1.0", a cross-vendor plugin packaging spec (root `plugin.json`, `skills/`, `mcp.json`), reported as published 2026-08-06 by Vercel with Amazon, Anysphere, GitHub, Microsoft, OpenAI, with Google joining; the same post says Anthropic is not a maintainer and Claude Code keeps its own plugin format. — [blakecrosley.com blog](https://blakecrosley.com/blog/agent-plugins-standard) (secondary; cites agent-plugins.org and vercel.com/blog/introducing-agent-plugins, which I did not fetch)
- Secondary (unverified): adoption counts of "30+" (April 2026) to "40+" tools for SKILL.md, Cursor skills support since v2.4 (2026-01-22), and a skills.sh registry with 90,000+ listings by July 2026. — [noqta.tn](https://www.noqta.tn/en/news/skill-md-open-standard-30-ai-coding-tools-adoption-2026); [mcp.directory blog](https://mcp.directory/blog/cross-agent-skills-cursor-codex-cline-antigravity-gemini-mastra-portability)

### Inferences
- `.agents/skills/` is the de facto shared project path (Codex and Gemini CLI both read it); Claude Code reads `.claude/skills/` and plugin `skills/`. A plugin wanting reach beyond Claude Code can keep spec-compliant skills in `skills/` and add thin per-agent manifests the way superpowers does, starting with the cheapest (e.g. `gemini-extension.json`, `.codex-plugin`), and documenting a manual copy into `.agents/skills/` as a fallback.
- sdd-convention's scaffold currently writes its rules block to CLAUDE.md only. Writing the block to `AGENTS.md` and having `CLAUDE.md` contain `@AGENTS.md` (or writing both) would make the convention visible to Codex, Cursor, Copilot, Gemini and others, while remaining correct for Claude Code on every version. Note the default precedence: if the project has a CLAUDE.md, Claude Code ignores AGENTS.md unless it is imported.
- The Stop hook and other hooks are Claude Code-specific; on other agents the convention would rely on instructions (AGENTS.md + skills) and on the Python linter in CI.

### Gaps
- `npx skills add` / skills.sh: no primary source was fetched; command syntax and registry size are unverified.
- The agentskills.io client showcase list was not fetched, so the exact set of supporting clients (Cursor, Copilot, OpenCode, etc.) is not confirmed from the primary source; Cursor, Copilot and OpenCode skill paths are unverified.
- Codex plugin manifest format (`.codex-plugin/plugin.json`), Codex hooks, and Gemini extension manifest details were not read from primary docs; only their existence in the superpowers repo layout is confirmed.
- Agent Plugins 1.0 is cited from one secondary blog only; the spec, maintainers and vendor support need verification at agent-plugins.org before any decision relies on it.
- Governance of the Agent Skills spec (whether it moved to a foundation) is not stated on the pages read; one secondary search result mentions AAIF governance in May 2026, unconfirmed.

## 5. Memory: CLAUDE.md imports, .claude/rules/, auto memory as a home for the plugin's rules block

### Takeaway
`.claude/rules/` (optionally path-scoped via `paths:` frontmatter) and `@path` imports are both viable, less invasive homes for the rules block than appending to CLAUDE.md, but plugins cannot ship always-loaded instructions themselves; the scaffold still has to write a file into the project (or inject through a SessionStart hook). Auto memory is Claude-written and not a distribution channel.

### Cited Findings
- CLAUDE.md and auto memory are both loaded every session and "Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead." — [Memory](https://code.claude.com/docs/en/memory)
- Size guidance: "target under 200 lines per CLAUDE.md file"; move instructions that matter for only part of the codebase into path-scoped rules; imports "don't reduce its context cost, because imported files load together with the CLAUDE.md that imports them". Files over 4 MiB are skipped. — [Memory](https://code.claude.com/docs/en/memory)
- `@path` imports: relative paths resolve relative to the importing file; recursive to a maximum depth of four hops; imports of external files in a project require a one-time approval dialog. — [Memory](https://code.claude.com/docs/en/memory)
- `.claude/rules/*.md`: rules with `paths:` frontmatter load when Claude reads, writes or edits a matching file (including `cat`/`head` on a single file); rules without `paths` load at session start; user-level rules live in `~/.claude/rules/`; symlinks are supported, with approval when the target is outside the working directory. `.claude/rules/` files keep loading alongside AGENTS.md. — [Memory](https://code.claude.com/docs/en/memory)
- Auto memory: written by Claude, per repository (shared across worktrees); the first 200 lines or 25KB of `MEMORY.md` load at session start. — [Memory](https://code.claude.com/docs/en/memory)
- `claudeMdExcludes` skips specific CLAUDE.md/rules files by glob; `InstructionsLoaded` hooks log which instruction files load and why. — [Memory](https://code.claude.com/docs/en/memory)
- A `CLAUDE.md` at a plugin's root is not loaded as context; the manifest's standard layout has no rules component. — [Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)

### Inferences
- Option A (minimal change): scaffold writes `docs/SDD-RULES.md` (or similar) and adds a single line `@docs/SDD-RULES.md` to CLAUDE.md, instead of a managed multi-line block. This keeps the plugin-managed text in its own file and makes upgrades a file overwrite, but triggers nothing new for other agents.
- Option B: scaffold writes `.claude/rules/sdd-convention.md` (always loaded, no `paths`) for the authority order, plus path-scoped rules such as `paths: ["docs/specs/**"]` for spec-editing rules and `paths: ["docs/decisions/**"]` for ADR rules. This removes the block from CLAUDE.md entirely and loads editing rules only when relevant. It is Claude Code-only.
- Option C (cross-agent): put the block in `AGENTS.md` and import it from CLAUDE.md with `@AGENTS.md`.
- Option D: keep no static block and inject both the rules summary and the active-spec index through the `SessionStart` hook. This only works where the plugin is installed and enabled, so collaborators without the plugin lose the rules; a committed file is more robust.
- Auto memory is not suitable: it is machine-local, Claude-authored and capped.

### Gaps
- The exact `paths:` frontmatter syntax examples and the Cowork-specific caveats were not read in full.
- No official guidance was found on how a plugin should install project-level rules (there is no documented "plugin ships rules" component); the options above are inferences.

## 6. Comparable plugins and packaging/onboarding practices

### Takeaway
superpowers is the reference for packaging: listed in `claude-plugins-official`, about 316.6k GitHub stars on the fetch date, zero-command onboarding via a SessionStart bootstrap, one shared skills tree with per-harness manifests, and scripted version sync.

### Cited Findings
- superpowers shows about 316.6k stars and 28.2k forks; installable with `/plugin install superpowers@claude-plugins-official` or from its own `obra/superpowers-marketplace`. — [obra/superpowers](https://github.com/obra/superpowers)
- Bootstrap: the `using-superpowers` skill is injected through a native `SessionStart` hook on Claude Code, Codex, Cursor, Gemini, Pi and others; the Pi extension re-injects after compaction; on harnesses without a post-compaction hook the README warns the bootstrap can be lost in long sessions. — [obra/superpowers](https://github.com/obra/superpowers)
- Skills trigger automatically, so no commands are needed after install; the README gives one install line per harness and an update line where the harness has one. — [obra/superpowers](https://github.com/obra/superpowers)
- Repo hygiene visible at top level: `RELEASE-NOTES.md`, `tests/`, `.version-bump.json` + `scripts/bump-version.sh`, `.pre-commit-config.yaml`, `CODE_OF_CONDUCT.md`; contributor rule that skill updates must work across all supported agents. — [obra/superpowers](https://github.com/obra/superpowers)
- Anthropic's own pre-release checklist asks for a root `README.md`, `description`/`author`/`homepage`/`repository` metadata, a clean `validate --strict`, a local-marketplace install test and an eval run. — [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md)

### Inferences
- Practices sdd-convention can copy at low cost: a SessionStart bootstrap (also matching `compact`) so the convention is present without the user invoking anything; a per-harness install table in the README; a version-bump script keeping `plugin.json`, `marketplace.json` and any other manifests in sync; `claude plugin validate --strict` plus the Python linter in CI; release notes file.

### Gaps
- Only superpowers was examined. Other comparable spec-driven-development plugins or kits (and their packaging) were not researched in this pass; another researcher's scope may cover them.
- superpowers' current version number and release dates were not visible on the page fetched; its hooks.json and per-harness manifest contents were not read.
